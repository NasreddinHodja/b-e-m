#+TITLE: TODO

The work queue, from the owner's =notes.org= (which isn't tracked). Each item says what's wrong, where, and the plan. =WAIT= says what input it needs; =DONE= says what was done, with the commit. Every visible change is also listed under "Changes since the port" in [[file:docs/parity.org][docs/parity.org]].

* TODO Port to SvelteKit
pnpm, TypeScript, ESLint + Prettier, Tailwind with the styles ported, logic encapsulated by responsibility, 1:1 with the legacy page.

Done in 2f33590 (the app), 8656109 (Pages deploy), 665fe09 (docs). Each tab is a route, each view's logic is in =src/lib/features/<view>/= with its state in a singleton class, and the backend, audio and score are separate modules ([[file:docs/architecture/overview.org][overview]]). Checked by screenshot diffs against =index.html=: 9 of 12 views pixel-identical on first load, the other 3 differ only in random content. Interactions weren't compared; that's under the tests item.

* WAIT Tests
Should we have tests? Yes: nothing guards the logic or the UI now.

Plan:
1. Unit tests (Vitest) for the pure modules: =ditado/{theory,rhythm,melody,model}.ts=, =contraponto/{rules,lilypond}.ts=, =acordes/chords.ts=, =harmonia3d/fields.ts=, =afinador/autocorrelate.ts=, =music/pitch.ts=. Seed =Math.random= where they draw.
2. Differential parity tests: the same functions run on the legacy =index.html='s code and on the port with the same seeds, outputs compared.
3. End-to-end (Playwright, Chromium) on the build: each view's main flow, scoring, sign-out, no console errors.

Waiting: it needs =vitest= and =@playwright/test= installed, and installing is the owner's call. Also: Playwright's own Chromium or the system =/usr/bin/chromium= (pad uses the system one)?

* TODO Ditado: staff not centred in /Mapa métrico/

* TODO Monospace everywhere
Every text is DM Mono, including prose (Manifesto, feedback, hints, the journal), where it reads worse.

Plan: map every mono use, view by view, and sort them: keep mono where it carries meaning (note and interval symbols, counters, tempo, LilyPond and note-entry fields, maybe small uppercase labels); use a readable sans or serif for prose and controls. Present the map and a font pairing for the owner to pick before changing anything: the choice of fonts is theirs.

* TODO Icons
The "icons" are Unicode and emoji glyphs (♬ ↔ ⚖ ◈ ◇ ♪ ◎ 📓 ⏱ 📖 ○ 🚪 📱 🎧 ▶ ⏹ 🗑 …), rendered at text size, inconsistent across systems, too small.

Plan: an icon library (Lucide, through =@lucide/svelte=, is the likely pick: tree-shaken SVG components, consistent stroke), sized to the text they sit with (16–20px in nav and buttons) and labelled for screen readers where they stand alone. Needs the owner's OK on the library and to install it.

* TODO Ditado: /ouça e adivinhe/ unreadable over the blurred staff
Gold text on the blurred, light paper has almost no contrast.

Plan: put the label on a dark, bordered chip so it reads over any background; check its contrast.

* TODO Portuguese and English, with a toggle
Every string is Portuguese and inline: in the pages, and in the logic modules' feedback (Acordes, Intervalos), the counterpoint rules' ~40 messages, Ditado's errors, the Manifesto's text.

Plan: a typed message catalogue per language and a =locale= state, kept in =localStorage= and defaulting to the browser's language; a PT / EN toggle in the sidebar.
