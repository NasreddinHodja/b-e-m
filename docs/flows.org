#+TITLE: UI flows: legacy vs port
#+OPTIONS: ^:{}

Every user flow in =legacy/index.html=, to run by hand on both apps and compare. Each flow: what to do, what both should do, where the code is.

* How to use

+ Legacy :: =legacy/index.html= needs real Firebase: serve it over http(s), sign in with a real account.
+ Port :: =pnpm dev= (local backend, signed in, data in localStorage) or a build with real Firebase ([[file:architecture/backend.org][backend]]).
+ Refs :: =L1884= is a line of =legacy/index.html=; port paths are under =src/=, =F/= = =lib/features/=, =R/= = =routes/(app)/=.
+ Random :: chords, intervals, melodies, distractors and option order are drawn at random; compare the behaviour, not the values.
+ Δ :: a deliberate difference, listed in [[file:parity.org][Parity]] (/Changes since the port/). Anything else that differs is a bug.
+ Bugs kept :: legacy bugs the port keeps are marked *kept*; they must behave the same.
+ ? :: not yet checked against the code; check while running it.
